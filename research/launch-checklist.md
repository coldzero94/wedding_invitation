# 실제 발송까지 남은 작업

> 2026-09-22 · Concept 01 사진 앨범 v2 · 현재 코드와 로컬 화면을 점검한 결과

[구현 상태](implementation-status.md) · [조사 목차](README.md)

현재는 가상 사진 3장으로 디자인과 기본 기능을 확인하는 시제품이다. 자동 검사 통과와 실제 하객에게 발송할 준비 완료는 별개다. 체크한 항목은 로컬 구현을 완료했으며, 나머지는 아직 남은 작업이다. 외부 서비스 정책을 새로 조사한 결과는 아니다.

## 1. 사진과 이야기를 실제 커플에 맞게 구성

기억에 남는 요소는 두 사람의 사진과 구체적인 이야기에서 만든다. 표지의 대표 사진, 짧은 이야기 3개, 전체 사진 갤러리를 구성하는 방향을 권장한다. 이야기 제목은 실제 경험을 듣고 정하며 현재의 ‘처음·여행·오늘’ 문구는 임시다. 동영상은 필요하지 않다.

- [ ] 대표 사진을 정하고 세로 모바일 표지와 가로 공유 이미지에서 얼굴이 잘리지 않는지 확인한다.
- [ ] 실제 에피소드를 짧게 적는다. 사진과 맞지 않는 샘플 이야기는 교체한다.
- [x] `albums`와 `photos` 데이터를 분리했다. 앨범은 고유 사진 ID로 여러 장을 묶고 첫 사진을 표지로 사용한다. 하이라이트는 앨범 단위로 표시하며 줄바꿈할 수 있다.
- [x] 본문 대표 컷은 `previewPhotoIds`로 선별하고, 나머지는 전체 갤러리에서 본다. 실제 사진 선별과 최종 장수 결정은 남아 있다.
- [x] 표지 이미지·설명·자르기 위치를 독립 설정하고 본문 사진별 자르기 위치도 설정할 수 있다.
- [ ] 공개 저장소에는 메타데이터를 제거한 웹용 사진을 넣고 촬영 원본은 별도로 보관한다.

완료 기준: 실제 사진이 들어간 상태에서 앨범 수와 페이지 길이가 의도대로 유지되고, 표지와 사진 설명이 일치한다.

## 2. 하객에게 필요한 정보를 먼저 찾을 수 있게 구성

현재 표지에는 이름·날짜·장소를 표시한다. 장소를 누르면 상세 예식 안내로 이동한다. 장소는 설정의 예식장 이름과 상세 위치를 조합하며 긴 이름은 줄바꿈한다. 실제 정보는 아직 가상 샘플이다.

- [ ] 실제 이름, 날짜·시각, 예식장·홀·층·도로명 주소를 입력한다.
- [x] 표지에서 이름·날짜·장소를 확인할 수 있게 했다. 실제 장소명 입력 후 사진과 함께 최종 확인한다.
- [ ] 예식 안내를 눌렀을 때 날짜·장소·길찾기에 바로 도달하는지 확인한다.
- [ ] 대중교통, 주차, 셔틀 등 실제 필요한 안내만 작성한다.
- [ ] 연락처와 선택적인 계좌 정보를 입력하고 번호·예금주를 대조한다. 사용하지 않는 영역은 최종 화면에서 숨긴다.
- [x] 발송 모드에서 빈 계좌·연락처 영역을 숨긴다. 연락처를 모두 생략하면 하단 연락 버튼을 공유 버튼으로 바꾼다.
- [x] 날짜·시간대·전화번호·지도 주소·계좌 형식·사진 설명을 빌드 시 검사한다. 발송용 빌드는 샘플 모드와 빈 예식장 주소를 거부한다. 정보의 실제 정확성은 별도 대조가 필요하다.
- [ ] 지도 링크가 동일한 이름의 다른 예식장이 아닌 실제 장소를 여는지 확인한다.
- [ ] 실제 정보가 모두 들어간 후 `isDemo`를 해제한다.

완료 기준: 청첩장을 처음 본 사람이 예식 시각과 장소를 찾고 길찾기·연락을 실행할 수 있다.

## 3. 실제 휴대폰 사용 흐름 보완

화면 폭별 Chrome 자동 검사는 통과했지만, 실제 Safari·Android·카카오톡 인앱 브라우저 확인은 아직 하지 않았다. 가상 데이터로 연락처·지도·계좌를 입력한 발송 모드와 생략한 발송 모드를 각각 검증했다. 실제 정보의 정확성과 외부 앱 연결은 별도로 확인해야 한다.

- [x] 사진·연락처·복사 창을 브라우저 방문 기록과 연결했다. 뒤로가기는 창을 닫고, 앞으로가기는 해당 창을 다시 연다. 사진 넘기기는 방문 기록을 추가하지 않는다. 실기기 검증은 별도로 남아 있다.
- [x] Chrome 자동 검사에서 사진 닫기 후 원래 위치와 포커스가 유지되는지 확인했다. 실제 휴대폰 확인은 아래 항목으로 남긴다.
- [x] 갤러리 사진의 로딩 안내와 실패 시 다시 불러오기 기능을 추가했다.
- [x] 실제 데이터를 변경하지 않고 별도 임시 사이트에서 발송 모드의 전화·문자·지도 링크 생성과 주소·계좌 복사, 빈 영역 숨김을 검증했다.
- [ ] iPhone Safari와 Android에서 사진 넘기기·확대 접근성·닫기 버튼·하단 버튼을 확인한다.
- [ ] 카카오톡에서 링크를 열어 공유, 링크 복사, 전화·문자, 지도 이동을 확인한다.
- [ ] 실제 전화·주소·계좌가 들어간 상태에서 복사 성공과 권한 거부 시 대체 흐름을 확인한다.
- [ ] 일정 파일을 휴대폰 캘린더로 가져와 한국 시각·장소가 맞는지 확인한다.
- [ ] 실제 사진으로 만든 배포 빌드를 느린 네트워크에서 확인한다. 현재 개발 서버의 전송량은 배포 성능 측정으로 사용하지 않는다.

완료 기준: 주요 모바일 환경에서 초대장을 읽고 사진을 보고 예식장으로 이동하는 흐름에 막힘이 없다. 실기기 미확인 항목은 완료로 표시하지 않는다.

## 4. 공유 미리보기와 배포 주소 확정

현재 OG 메타데이터와 공유 이미지 생성은 구현했지만 기본 주소는 localhost다. 수동 실행용 GitHub Pages 워크플로 파일은 작성했다. GitHub 저장소·실제 Pages 주소·외부 배포 연결은 아직 없다.

- [ ] 실제 저장소와 Pages 주소를 확정하고 `SITE_URL`·`BASE_PATH`를 적용한다.
- [x] GitHub Actions 빌드·배포 설정 파일을 작성했다. Node 24에서 검사와 발송용 빌드를 실행하며 Pages의 도메인·경로를 사용한다. YAML 구조를 확인했으며 GitHub 실행은 남아 있다.
- [ ] 사진·폰트·일정 파일이 실제 배포 경로에서 열리는지 확인한다.
- [ ] 공유 카드의 사진 자르기, 이름, 날짜, 장소를 정하고 카카오톡에 실제 링크를 붙여 확인한다.
- [ ] 실제 배포 HTML의 canonical·OG 주소에 localhost가 남지 않는지 확인한다.

카카오 전용 SDK는 선택 사항이다. 먼저 현재 시스템 공유·링크 복사와 실제 링크 미리보기를 검증한다.

완료 기준: 최종 HTTPS 주소를 다른 휴대폰에서 열 수 있고, 공유 미리보기가 실제 예식 정보를 표시한다.

## 5. 최종 주소로 QR 생성하고 인쇄 확인

- [ ] 실제 배포 주소가 열린 뒤 QR SVG·PNG를 생성한다.
- [ ] 화면에 표시한 QR과 실제 인쇄 크기의 QR을 각각 휴대폰 카메라로 스캔한다.
- [ ] 스캔 결과가 최종 청첩장 주소와 일치하는지 확인한다.
- [ ] QR 주변 여백과 대비를 유지하고 작은 장식이나 로고를 추가한 경우 다시 스캔한다.
- [ ] 인쇄 후에는 저장소 이름·배포 경로를 유지한다. 사진과 문구를 수정할 때도 같은 주소로 배포한다.

완료 기준: 다른 휴대폰에서도 실제 인쇄물의 QR로 초대장을 열 수 있다.

## 권장 진행 순서

1. **로컬 구현 완료:** 앨범·갤러리 구조 분리, 표지 장소 표시, 모달 뒤로가기 처리.
2. **후속 개발:** 빈 정보 영역 처리, 설정 검증, 갤러리 로딩 실패 복구, 발송용 빌드와 배포 워크플로를 보완했다. 가상 데이터로 발송 모드를 검증한다.
3. 실제 사진과 예식 정보를 받아 페이지 분량·사진 자르기·문구를 마무리한다. 사진 메타데이터와 실제 사진 수에서의 성능도 확인한다.
4. 배포 주소와 공유 미리보기를 확정하고 실기기에서 확인한다. 기기별로 드러나는 동작 차이는 추가 수정한다.
5. QR 생성과 인쇄 검증을 마친 뒤 하객에게 발송한다.

배포 파일 작성에 참고한 공식 자료: [GitHub Pages 사용자 정의 워크플로](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), [Astro 배포 안내](https://docs.astro.build/en/guides/deploy/github/), [Pages 도메인·경로 출력값](https://github.com/actions/configure-pages/blob/v5/action.yml). 파일 작성은 실제 배포 성공을 의미하지 않는다.

현재 범위에서는 별도 서버·S3·DB, 동영상, 방명록, 로그인, 참석 응답 수집은 추가하지 않는다. 추가 디자인 레퍼런스를 계속 늘리기보다 선택한 컨셉을 실제 사진과 하객의 사용 흐름에 맞추는 작업을 우선한다. Git 초기화와 외부 배포는 아직 수행하지 않았다.
