## QR 코드 계획

외부 무료 QR 사이트나 이른바 동적 QR 서비스를 사용하지 않는다. 일부 서비스는 나중에 리디렉션을 중단하거나 구독을 요구할 수 있다. 최종 청첩장 URL 자체를 정적 QR에 직접 넣으면 QR에는 만료 개념이 없다.

권장 작업 순서:

1. GitHub 계정명과 공개 저장소명을 정한다.
2. `https://사용자명.github.io/저장소명/`로 실제 배포한다.
3. URL과 OG 미리보기가 정상인지 확인한다.
4. 프로젝트의 QR 생성 스크립트로 SVG와 PNG를 만든다.
5. SVG는 종이 인쇄물에, 고해상도 PNG는 디지털 시안에 사용한다.
6. 실제 인쇄 크기로 아이폰과 갤럭시 여러 기종에서 스캔한다.
7. 스캔 검증을 마친 뒤 종이 청첩장을 인쇄한다.

추천 생성 설정:

```text
내용: https://사용자명.github.io/저장소명/
오류 정정: Q
여백: 4 modules
전경: 검정 또는 매우 짙은 단색
배경: 흰색 또는 매우 밝은 단색
출력: SVG + 1024px PNG
```

QR 주위에는 네 방향으로 최소 4모듈의 빈 공간이 필요하다. QR 위에 사진이나 로고를 겹치는 장식은 피한다. 인쇄 시에는 약 25~30mm 이상을 시작점으로 두고 실제 종이와 동일한 조건에서 테스트한다.

구현 후보는 오픈소스 `qrcode` 패키지다. SVG/PNG 출력, 오류 정정 단계, 색상과 여백을 설정할 수 있다.

- [node-qrcode 저장소 및 사용법](https://github.com/soldair/node-qrcode)
- [DENSO WAVE QR 여백 지침](https://www.qrcode.com/en/howto/code.html)
- [DENSO WAVE QR 오류 정정 설명](https://www.qrcode.com/en/about/error_correction.html)
- [인식 문제 사례](https://www.qrcode.com/en/howto/trouble.html)

GitHub Pages를 끄거나 계정명·저장소명을 바꾸면 인쇄한 QR의 목적지가 달라질 수 있다. QR 인쇄 후에는 최종 배포 주소를 유지한다.

## 완전 무료 방식의 남는 위험

유료 도메인을 쓰지 않으면 QR은 GitHub Pages의 `github.io` 주소와 저장소 경로에 묶인다. 나중에 호스팅 업체를 바꿔도 기존 QR을 새 주소로 리디렉션할 독립 도메인이 없다. 무료 단축 URL을 중간에 넣는 방법은 서비스 하나를 더 의존하게 되어 오히려 위험하다.

따라서 다음 운영 규칙을 적용한다.

- GitHub 계정명·저장소명은 QR 인쇄 전에 확정하고 이후 바꾸지 않는다.
- GitHub 저장소를 삭제하거나 Pages 배포를 비활성화하지 않는다.
- 계정에 2단계 인증을 설정하고 복구 코드를 보관한다.
- 소스와 빌드 산출물을 별도로 백업해 둔다.
- 인쇄 직전 최종 URL을 여러 네트워크에서 확인한다.
- 예식 후에도 QR을 유지하려면 같은 Pages 주소에 개인정보를 제거한 보관용 화면을 배포한다.

GitHub Free는 공개 저장소의 Pages 사용을 지원한다. 대안인 Cloudflare도 무료 플랜을 제공한다. 다만 모든 외부 무료 서비스 정책은 장기적으로 바뀔 수 있으므로, 순수 정적 결과물을 유지해 다른 호스팅으로 쉽게 옮길 수 있게 만든다.
