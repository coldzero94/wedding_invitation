# Concept 02 — 사진 기록장과 반응형 설계

> 작성일: 2026-09-22 · 사진 전용 청첩장 · 새 디자인 제안, 최종 선택 전

[조사 목차](README.md) · [이미지 시안](mockups/README.md)

## 디자인의 중심

청첩장을 보는 하객이 두 사람의 사진과 이야기를 살펴보고, 예식 일시와 장소를 빠르게 찾도록 한다. `같이 걷다, 함께 살기로.`라는 문장과 사진 사이를 잇는 파란 선을 시각적 중심으로 삼는다.

현재 두 사람의 실제 취미·연애 이야기는 제공되지 않았다. 여행 기록장은 탐색용 콘셉트이며 사진·이름·날짜·여행 이야기는 가상 예시다. 실제 여행 사진이 적다면 같은 구조를 `우리가 모은 평범한 날들`이라는 일상 기록장으로 바꿀 수 있다.

## 두 가지 배치 검토

| 검토안 | 구성 | 판단 |
| --- | --- | --- |
| 자유로운 스크랩북 | 사진 여러 장 겹침, 작은 메모, 도장, 티켓 | 개성은 강하지만 작은 화면의 정보 밀도가 높아짐 |
| 정돈된 사진 기록장 | 대표 사진 한 장, 날짜 띠, 사진 사이를 잇는 선 | 모바일 가독성과 개성을 함께 유지하는 최신 제안 |

첫 모바일 시안의 항공권 모양 장식, 비행기 아이콘, 작은 메모는 실제 여행 취향을 확인하기 전에 확정하지 않는다. 후속 반응형 시안에서는 이를 줄이고 날짜를 사진 위로 이동했다. 두 이미지가 다르면 반응형 시안의 정보 우선순위를 따른다.

## 색·글자·사진 규칙

| 역할 | 제안 |
| --- | --- |
| 종이 바탕 | 안개색 파랑 `#E5EFF5` |
| 제목·주요 버튼·사진 연결선 | 코발트 `#2448B5` |
| 본문 | 짙은 남색 `#182846` |
| 예식 날짜 강조 | 노랑 `#F4D263`, 남색 글자 |
| 사진 테두리·본문 면 | 흰색 `#FFFFFF` |

- 대표 문구만 직접 쓴 듯한 손글씨 형태로 제작한다. 최종 문구가 정해지면 별도 제목 자산으로 만들고 접근 가능한 텍스트도 제공한다.
- 일반 소제목은 마루 부리, 본문·버튼·날짜는 Pretendard 또는 시스템 글꼴을 후보로 둔다. 폰트 사용 조건은 [폰트 조사](design-direction.md)를 따른다.
- 본문 16~18px, 줄 간격 약 1.6, 보조 설명도 14px 전후를 목표로 한다. 실제 기기 검증에서 조정한다.
- 손글씨는 제목과 짧은 사진 메모에만 사용한다. 날짜·주소·계좌번호는 명료한 본문 글꼴로 표시한다.
- 사진 회전은 대표 사진 테두리에만 약 1~2도로 제한한다. 설명과 버튼은 회전시키지 않는다.
- 연결선은 장식이다. 선이 없어도 사진과 글의 순서만으로 이야기를 이해할 수 있어야 한다.
- 사진 속 인물 위치를 개별 설정해 얼굴이 잘리지 않게 한다. 확대 보기에서는 원래 사진 비율을 유지한다.

## 화면 크기별 배치

아래 폭은 구현을 위한 제안값이며 실제 콘텐츠와 기기에서 검증한 뒤 조정한다. 기종명으로 분기하지 않고 사용 가능한 화면 폭으로 결정한다.

| 화면 폭 | 본문 배치 | 사진 이야기 | 이동 방식 |
| --- | --- | --- | --- |
| 320~359px | 1열, 좌우 여백 16px | 사진·캡션을 순서대로 쌓음, 겹침 제거 | 하단의 예식 안내·연락하기 두 버튼 |
| 360~599px | 1열, 좌우 여백 20px | 큰 사진 한 장과 캡션, 썸네일만 가로 넘김 | 모바일 하단 메뉴, 자연스러운 세로 스크롤 |
| 600~899px | 표지 1열, 읽기 폭 제한 | 공간이 허용되면 사진 카드 2열 | 충분한 버튼 크기 유지, 긴 본문은 넓히지 않음 |
| 900~1199px | 표지와 본문 2열 | 본문 폭에 따라 사진 카드 1~2열 | 상단 링크로 전환, 하단 고정 메뉴 해제 |
| 1200px 이상 | 전체 최대 폭 약 1280px, 표지 40%·본문 60% | 사진 카드 2열, 예식 안내 가로 배치 | 상단 링크, 페이지 전체 스크롤 |

큰 화면에서 모바일 화면 전체를 확대하지 않는다. 대표 사진·제목과 본문이 나란히 놓이고, 본문 글자 크기는 적정 수준으로 유지한다. 작은 화면에서는 두 열을 한 열로 바꾸며 장식의 수를 줄인다.

## 모바일의 정보 순서

```text
두 사람의 이름 / 짧은 제목
예식 날짜 · 시간 · 장소
대표 사진
짧은 초대 문장
사진 이야기 보기
사진과 캡션의 연속
상세 예식 안내 · 지도
연락처 · 마음 전하실 곳
감사 문구
```

첫 화면은 `초대장 열기`를 눌러야만 들어갈 수 있는 구조로 만들지 않는다. 날짜·시간·장소를 대표 사진 위에 두어 사진이 아직 로딩 중이어도 정보가 보이게 한다. 화면 높이가 짧거나 글자를 키웠을 때는 콘텐츠가 자연스럽게 아래로 이어져야 하며, 한 화면에 억지로 압축하지 않는다.

## 한 손 조작과 접근성

- 주요 버튼 높이는 최소 48px을 목표로 하고, 작은 아이콘도 충분한 터치 영역과 이름을 제공한다.
- 모바일 하단 메뉴는 `예식 안내`, `연락하기` 두 개만 둔다. 실제 섹션으로 이동하는 링크이며 순서 변경이나 로그인은 필요 없다.
- 홈 인디케이터 영역을 고려한 하단 여백과 메뉴 높이만큼의 본문 여백을 둬 마지막 내용이 가려지지 않게 한다.
- 두 영역이 각각 스크롤되는 구조는 피하고 문서 전체가 세로로 스크롤되게 한다.
- 사진을 넘길 때 스와이프와 이전·다음 버튼을 모두 제공한다. 사이트 전체의 스크롤을 가로로 바꾸지 않는다.
- 200% 글자 확대 시 날짜 띠와 메뉴 높이가 늘어날 수 있게 한다. 제목 줄바꿈과 버튼 너비를 고정하지 않는다.
- 확대 갤러리는 닫기 버튼, 키보드 이동, 포커스 복귀를 포함한다.
- 손글씨·텍스처·얇은 장식선으로 날짜와 길찾기 글자의 가독성을 떨어뜨리지 않는다.

## 동영상 없이 만드는 움직임

커플 동영상은 없다. 기본 화면은 사진과 글만으로 완성한다. 선택적인 움직임은 첫 대표 사진이 자리 잡는 짧은 전환, 사진을 넘기는 동작 정도로 제한한다. 인터랙션을 구현할 때 별도로 성능을 확인하며, 모션 감소 설정에서는 정지 상태를 바로 보여 준다.

재생 아이콘, 영상 길이, 재생 막대, 자동 진행하는 스토리는 사용하지 않는다. 이미지 시안에 보이는 사진은 실제 구현에서 독립 이미지 자산으로 준비한다. 목업 PNG 한 장을 통째로 웹페이지 배경으로 사용하지 않는다.

## 사진 로딩과 무료 배포

- 공개 GitHub 저장소에 웹용 기준 사진을 넣고 GitHub Pages에 정적 배포한다.
- 화면 크기에 맞는 이미지와 지연 로딩은 [사진 관리 계획](photos.md)을 따른다.
- 첫 대표 사진은 우선 표시하고, 아래쪽 사진은 가까이 도달했을 때 로딩한다.
- 종이 질감과 연결선은 작은 장식 자산이나 CSS·SVG로 만들고, 큰 합성 PNG를 여러 장 다운로드하게 하지 않는다.
- QR은 [QR 계획](qr.md)에 따라 최종 배포 URL이 확정된 뒤 생성한다.

## 구현 후 확인할 항목

1. 폭 320·360·390·430·768·1024·1440px에서 의도하지 않은 가로 넘침이 없는지.
2. 높이가 짧은 화면과 가로 방향에서 날짜·사진·메뉴가 겹치지 않는지.
3. iPhone Safari, Android Chrome, 카카오톡 인앱 브라우저에서 하단 메뉴가 내용을 가리지 않는지.
4. 글자 200% 확대, 긴 실제 이름·장소명, 여러 줄 주소에서도 카드가 자연스럽게 늘어나는지.
5. 사진 로딩 전에도 텍스트와 예식 안내 링크를 사용할 수 있는지.
6. 썸네일을 손으로 넘기거나 버튼으로 이동하고 사진 확대를 닫을 수 있는지.

현재 산출물은 생성 이미지와 설계 문서다. 이미지에 표시된 360·390·1280은 목표 화면 폭을 뜻하며, 생성 이미지의 실제 픽셀 크기나 반응형 동작 검증 결과가 아니다. HTML/CSS 구현과 기기 테스트는 아직 진행하지 않았다.
